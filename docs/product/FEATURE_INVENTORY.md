# Authoritative feature inventory

This is the canonical scope and traceability ledger. It defines 200 independently testable features. IDs are permanent. Current status is based on the 2026-07-16 audit; a reusable prototype pattern does not make the legal feature implemented.

## Reading each entry

Every row contains all required feature fields in compact form:

- **Problem / behavior / workflow** states the user problem, visible behavior, and primary flow.
- **Data / owner / dependencies** names required data, its source-of-truth owner, and prerequisite IDs or boundaries.
- **Integrity / failure / originals / audit** states security or integrity concerns, failure and recovery behavior, whether originals are affected, and audit obligations. `O:no` means the feature must not modify originals. `O:approved tx` means only an explicitly approved file transaction may do so.
- **Plan** is phase, priority, and current repository status.
- **Acceptance criteria** are testable. All P0/P1 entries have explicit criteria.
- **Non-goals / open decisions** constrain implementation and identify unresolved design choices.

Priority is P0 structural/data safety, P1 first usable workflow, P2 complete trial preparation, P3 advanced productivity, P4 optional future. Status vocabulary is: Implemented and verified; Implemented but insufficiently tested; Partially implemented; Prototype or experimental; Documented only; Missing; Potentially obsolete; Requires architectural decision.
