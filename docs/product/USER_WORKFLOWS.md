# End-to-end user workflows

The file safety and data-model documents govern every flow. “Source unchanged” means content and path both stay unchanged unless the flow explicitly invokes an approved `FileOperationTransaction`.

| # | Workflow | User actions | System actions and records/files | Validation and confirmation | Audit, error recovery, undo |
|---|---|---|---|---|---|
| 1 | Import existing case folder (`APP-014`, `IMPORT-001`, `FILE-001`) | Choose profile/root; review authorization, scan summary, mappings and warnings; approve case creation. | Read-only scan creates staged Case/CaseFile/FileVersion/metadata plan; commit creates case DB/catalog. No source files/folders created, moved, renamed or edited. | Canonical boundary, permission, duplicates, risky files, space/schema; explicit approval binds plan. | Import planned/committed/cancelled. Crash resumes/rolls back staged DB; source unchanged. Undo archives/removes newly created app records only if no later work, never files. |
| 2 | Create case from scratch (`APP-015`, `CASE-001`) | Choose blank/template, root/managed storage, metadata and optional folder plan; approve. | Atomically creates Case/profile references, DB, audit; optional new empty directories only if previewed. Existing files unchanged. | Root/bookmark/collision/template version and no prior-client data. | Case creation event. Failure removes incomplete managed artifacts; undo archives case and optionally offers separate safe empty-folder cleanup plan. |
| 3 | Add source and classify as evidence (`IMPORT-002`, `EVID-001`) | Import by reference/managed copy; inspect metadata/preview; create evidence; add neutral/internal fields/source/custodian. | Catalog CaseFile/FileVersion; if copy mode, stage/copy/hash managed original; create EvidenceItem/EvidenceSource links. External source unchanged. | File version/hash/type/quarantine, copy destination, evidence provenance and confidentiality. | Import/evidence/link events. Failed copy unpublished and cleaned; failed evidence DB tx rolls back. Undo removes evidence/link, not catalog/source; copied source retention is separate reviewed cleanup. |
| 4 | Evidence to proposed exhibit (`EXH-001`, `EXH-005`) | Select evidence/source ranges; enter neutral title/number policy; preview page plan; create proposed exhibit. | Creates Exhibit UUID, draft ExhibitRevision, ExhibitPages pinned to FileVersions; optional preview derivatives. Originals unchanged. | Ranges, missing pages, source roles, number conflict, internal/export separation. | Exhibit/revision creation events. Validation failure keeps draft; undo archives proposed exhibit if unused, preserving audit. |
| 5 | Reorder and renumber exhibits (`EXH-010`–`012`) | Drag/group/filter; pin/reserve; request renumber; review complete mapping/dependencies; approve and optionally lock. | Creates order/renumber plan and atomically writes new assignments/order revision; dependent projections marked/rebuilt. No source files changed. | Locked numbers, conflicts/gaps, stale references, binder/list impact. | Batch old/new mapping and lock events. DB failure rolls back. Undo/restore creates a new ordering revision after revalidation; never edits history. |
| 6 | Generate draft binder (`BIND-001`–`008`) | Create draft/profile/volumes; review validation/page plan; start/cancel; inspect preview/manifest. | Freeze inputs, create derivatives/page plan, stage PDFs, reconcile, publish draft volumes/manifest/ExportRecord. Originals unchanged. | Exact revisions, missing/duplicate pages, ranges/labels, redaction/confidentiality, disk. | Job checkpoints/generation/export events. Crash resumes/restarts/cleans; partial files never final. Undo removes disposable draft output only if unreferenced; revision remains. |
| 7 | Replace source after exhibit creation (`FILE-002`, `EXH-007`) | Import/relink replacement as new version/source; compare; choose affected exhibit; review successor revision and stale dependents; approve. | Creates FileVersion/EvidenceSource lineage and new ExhibitRevision; old exhibit/binder revisions remain pinned. Originals old/new unchanged. | Identity versus replacement, hash/version, page mapping, missing pages, binder/export impact. | Replacement/lineage/revision events. Failure preserves old current state; user can abandon draft. Undo supersedes new draft/current pointer if not finalized, never deletes versions. |
| 8 | Add witness and associate exhibits (`WIT-001`, `WIT-005`) | Select/create person; set role/restrictions/call state; link exhibits with foundation/authentication roles; add prep tasks. | Creates Witness, WitnessExhibitLinks, optional Tasks/notes. No files changed. | Duplicate person review, contact restriction, exhibit stable ID/status, internal/export visibility. | Witness/link/task events. DB tx rollback on failure. Undo removes links/task instance or archives witness while preserving audit. |
| 9 | Build sourced factual timeline (`TIME-001`–`005`) | Add event precision/neutral fact; attach citations/participants/evidence; add separate strategy; mark dispute/accounts; confirm. | Creates TimelineEvent, citations/links/account records and provenance states. No files changed. | Citation resolves exact FileVersion/page; approximate/unknown date honesty; confirmation authority; duplicate/conflict findings. | Event/source/confirmation events. Missing source becomes tombstone/stale warning. Undo creates version/supersession, not erasure. |
| 10 | Add hearing and confirm deadlines (`CAL-001`, `CAL-005`–`007`) | Add hearing/source; select reviewed rule reference/inputs; inspect calculation; edit/confirm/reject; create tasks/reminders. | Creates CalendarEvent, Deadline suggestion/calculation/rule link, separate confirmation decision and related Tasks. No files changed. | Jurisdiction/rule/effective date/trigger/time zone/excluded days; suggested versus confirmed UI. | Event/calculation/decision/task events. Missing inputs keep incomplete suggestion. Trigger change creates review candidate; old confirmed remains. Undo of confirmation is a new corrective decision. |
| 11 | Rename/reorganize files safely (`ORG-002`–`010`) | Select files; request deterministic/AI suggestions; edit plan; inspect reasons/collisions/refs; approve exact digest; monitor. | Durable FileOperationTransaction journals creates/moves/renames, verifies content identity, updates catalog/refs and audit. Content unchanged; approved paths change. | Authorized roots, real paths, symlinks/hard links, versions, case/Unicode collisions, disk/permissions; revalidate at approval. | Proposal/approval/step/completion events. Crash enters recovery; rollback compensates and verifies. Undo creates inverse tx and blocks on external drift. |
| 12 | Finalize then revise binder (`BIND-009`, `BIND-010`) | Resolve blocking validation; approve finalization; later choose Reopen as New Revision, change inputs and regenerate. | Locks revision/output/manifest/hash; later creates successor draft and new outputs. Originals and prior binder files unchanged. | Validation/reconciliation, profile/disclosure, exact input/output hashes; warned reopen. | Finalize/reopen/generate events. Failure before publish leaves prior final. Finalization has no destructive undo; corrective successor revision is the remedy. |
| 13 | Archive and restore case (`BACKUP-003`, `BACKUP-005`) | Run final backup/validation; choose archive/read-only; later preview restore/path mappings and approve new writable location. | Creates verified archive package/manifest, locks case read-only; restore creates validated case copy preserving IDs/history. External originals unchanged. | Package/schema/hashes, missing external sources, destination permissions/collisions. | Archive/export/restore events. Failed package/restore unpublished and current case untouched. Undo archive is controlled reopen; restore deletion requires separate safe cleanup. |
| 14 | Recover interrupted file transaction (`ORG-009`, `BACKUP-004`) | Relaunch; open Recovery Center; inspect journal/disk comparison; choose resume/rollback/manual mapping when offered. | Reconciles stable identities/hashes/paths/DB; idempotently completes or compensates; updates catalog/audit only after verification. Source paths may reflect approved partial steps; content must remain unchanged. | Never infer from name alone; ambiguous/external changes require user. | Recovery decision/outcome events. Repeated failure remains NeedsUser/read-only. Undo available only after a verified completed state. |
| 15 | Recover interrupted binder generation (`BIND-007`, `BACKUP-004`) | Relaunch; inspect job/input freshness/staged outputs; resume/restart/clean staging. | Verifies checkpoint/input versions; resumes safe nodes or discards staged derivatives; keeps previous published binder. Originals unchanged. | Manifest/checkpoint/hashes/disk space and no stale input. | Recovery/generation events. Ambiguous stage never publishes; cleanup is retryable. Undo removes only disposable staging/cache. |

## Cross-workflow confirmation rules

DB-only low-risk edits may use standard Save and version history. Anything changing source paths, finalization, confirmed deadlines, external disclosure, confidentiality override, restore destination, or AI external transmission requires an exact-impact confirmation. Confirmations are not reusable blanket permission.
